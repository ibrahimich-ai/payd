# Аудит UUID

Найди все места, где создаются ID записей, и убедись, что используется единая точка генерации `PaydDB.utils.uuid()`.

## Что искать (Grep по всему репо)
- `Date.now()`, `Math.random()`, `crypto.randomUUID(`, `new Date().getTime()` рядом с присвоением `id` / `_id` / `appId` / `number`
- Ручная склейка ID: шаблонные строки с префиксом + счётчик/таймстемп
- Прямые присвоения `id:` в объектах перед записью в `PaydDB` / localStorage
- Любая генерация ID в обход `PaydDB.utils.uuid()`

## Проверь во ВСЕХ таблицах, не только applications
В ROADMAP.md отмечено, что этот класс бага затрагивает и другие таблицы. Пройди по: applications, clients, contracts, kassa/операции, employees, partners, products.

## Отчёт
Для каждой находки: файл, строка, текущий код, чем грозит (дубликаты / фантомные записи / сбой outbox), как исправить через `PaydDB.utils.uuid()`. В конце — короткий вывод: чисто / список проблем по приоритету. Ничего не правь, только отчёт.
